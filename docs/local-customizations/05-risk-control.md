# 风控 patch：三类行为及合并处理

归属：功能补强 → 风控。总清单见 [FEATURES](FEATURES.md)，恢复原则见 [GUIDANCE](GUIDANCE.md)，执行顺序见 [WORKFLOW](WORKFLOW.md)。

上游审计基线：`7afb6b61df84ccca07a9cfa0a94354466402af84`（v0.27.0）。结论来自该提交源码和依赖核查，不能自动沿用为后续版本的结论。

## 分类定义

- A：当前存在且必须限制。合并后确认禁用状态，新增实现同样禁用；发现漏网实现则修复后才能完成验证。
- B：当前存在且无需限制。保留正常功能及本 fork 指定配置，不额外添加关闭、弹窗或拦截。
- C：当前未发现，合并时监控。每轮检查是否新增；命中后按表中政策处理，不能永久写成“不存在”。

产品账号指控制本软件使用资格的账号；Git 作者身份、仓库凭据、托管平台及 AI 账号不属于产品账号。自动更新检查不等于强制升级；普通外联不等于遥测；AI 审查不等于完整 PR Review；Tauri 静态插件不等于插件市场。

## A：项目中存在，必须限制

| ID | 行为 | 上游现状 / fork 处理 | 合并检查入口 | 完成条件 |
| --- | --- | --- | --- | --- |
| RC-A01 | 网站开发/构建工具遥测 | Astro 依赖 `@astrojs/telemetry`；核查版本默认启用并向 `https://telemetry.astro.build/api/v1/record` 上报。本 fork 四个 Astro 命令已设置 `ASTRO_TELEMETRY_DISABLED=1` | `apps/website/package.json`、根脚本、CI/网站/发布工作流、Bun 锁文件及 Astro 遥测实现；新直接调用 Astro 的入口也要检查 | dev/build/preview/typecheck 入口均显式禁用；依赖升级后确认开关仍生效。运行相应检查，不仅确认变量文本存在 |

统一政策：遥测、使用统计、跟踪上报、自动崩溃上报必须禁用。不能通过改名、换端点或仅关闭 UI 入口绕过。崩溃信息本地显示、用户主动复制不属于自动上报。遥测包仍在依赖树并不表示必须删包，关键是所有受控执行入口均不可启用上报；应用启动或核心操作不得依赖上报成功。

| RC-B05 | 自托管与托管平台账号 | GitHub/GitLab/Bitbucket 等集成和凭据；含当前自托管协议适配 | 允许，不因本风控清单更改 HTTPS/HTTP 回退策略或增加限制 | `forge`、`accounts`、`account_check` 及 provider；账号仅用于对应辅助能力，不变为产品授权 |

B 类“无需限制”不是承诺没有数据传输；是用户已确认允许该功能，不在此次同步中擅自加限制。若上游从普通辅助功能变为遥测或产品门禁，按实际行为转入 A/C 处理。

## 每轮审查方法与输出

1. 记录本轮上游旧 SHA、新 SHA 和 fork 基线。对比上游两版的依赖、启动、路由、HTTP、更新、账号、插件及构建入口；同时检查 fork 最终结果，不能只看冲突文件。
2. 搜索 SDK、telemetry/analytics/crash、login/license/entitlement、动态加载和网络入口只是定位手段。沿调用链确认数据、目的地、触发方式、默认值及是否阻断核心功能；不能以单次关键字搜索证明不存在。
3. A 类逐项确认禁用；B 类逐项确认保留与指定配置；C 类逐项确认未新增或给出命中证据。没有相关代码变化也记录“未变化，复核入口”。
4. 新 SDK 或不明网络行为无法确定用途时记为“待确认”，不能记为“未发现”；涉及待决策能力时，该项不能标为完成。其他独立同步工作可继续。
5. 输出每个 ID 的结论、源码路径/符号、处理 diff、验证结果。A 类已修复后更新本表；C 类接受的新功能迁入 B 类，要求禁用的迁入 A 类。

本文件是风控行为清单，不是完整的依赖供应链审计。此政策不增加对用户已允许的 AI、自托管、更新、Fetch、头像等辅助功能的限制。
