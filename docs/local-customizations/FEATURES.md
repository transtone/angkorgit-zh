每条记录按“标题 → 状态 → 记录更新 → 行为 → 维护入口”排列，字段各占一行，段落之间空一行。记录更新只表示文档最近核对时间，不代表功能首次完成时间；没有可靠日期的历史记录不补写日期。

### 3. 易用性增强

#### 分支与标签交互优化

状态：已实现。
记录更新：2026-11-11。

**分支标签与引用浮层**

- 当前分支优先显示，标记与实际检出分支一致。
- 独立远端引用保留远端前缀，避免同名引用混淆。
- 悬停不撑宽引用列，原标签与 `+N` 位置不变。
- 更多引用以主题实底浮层覆盖原标签，首项按实际坐标左上对齐。
- 浮层不透明，遮住下方标签和图线；无边框、阴影或位移动画，限制尺寸并支持滚动。
- 浮层打开时抑制原生提示，避免遮挡。
- 引用右键菜单标题与来源标签轨道色一致，标题加粗、增加留白并加分割线，操作项保持原色。
- 从浮层打开右键菜单时保持引用列表，菜单关闭后释放。

**远端状态与过期引用**

- 分支与 tag 共用认证只读查询，各远端结果独立更新。
- 重查期间保留已有显示，旧响应不得覆盖新结果。
- tag 区分已同步、仅本地、未知及同名对象不一致。
- 比较标签直接 OID，包括附注与签名变化。
- 支持后台、手动检查及选择推送远端；已同步禁用推送，不默认强推。
- 过期跟踪分支显示为灰色、断云图标及完整远端前缀。
- 查询失败不构成新的过期证据，也不清除已确认的过期分支标记。
- 单条删除前重查远端，并锁定核对本地 OID。

实现与验证：[06 远端引用状态](06-remote-ref-status.md)。

**双向严格快进菜单**

- 当前分支可以快进到所选分支。
- 所选本地分支可以快进到当前分支。
- 拒绝分叉、覆盖本地修改及修改其他工作树占用的分支。

维护入口：[07 整体交互](07-branch-tag-interactions.md)。

## 三、合并与增强流程

整体顺序：先合并上游 → 按功能清单分析差异 → 形成分类文件列表 → 按依赖顺序更新 → 验证结果。

### 1. 先合并上游代码

- 记录合并前的 fork 提交、上次上游基线和本次上游目标。
- 保留恢复本地增强所需的差异。
- 先完成上游代码合并和冲突解决，原则上以上游最新实现、结构及接口为准。
- 冲突处不为保住旧增强而退回旧实现；被覆盖的增强记录下来，后续按新结构恢复。
- 正常合并且没有冲突的增强不主动删除。
- 上游优先不等于把整个仓库替换成上游副本。

本阶段产出：无未解决冲突的合并代码、冲突处理记录、上游变更范围。

此时不把增强恢复或构建验证标为完成。

### 2. 对照功能清单逐项分析

分析合并后的实际代码，逐条核对第二部分，检查范围不能只限于冲突文件。

#### 逐项结论

- **完整保留**：行为仍符合要求，无需修改。
- **上游已等价实现**：复用上游能力，不重复恢复。
- **被覆盖或部分丢失**：列出需要恢复的行为。
- **接口或结构变化**：列出需要适配的行为。
- **待确认**：证据不足或新增能力尚未决定，单独记录。

#### 每个待更新项分行记录

- 对应功能。
- 当前差异。
- 预期行为。
- 涉及的源码、配置、词典和测试文件。
- 前置依赖。

按工具链、国际化、易用性、隐私安全和发布适配分类。同一文件涉及多项增强时合并安排，避免重复覆盖。

#### 风控结论

- **A 类**：核对禁用是否保留，缺失的列入修复。
- **B 类**：保留正常功能，只恢复国内头像、fork 更新地址等已确认适配。
- **C 类**：检查是否新增。新增遥测直接列入禁用；其他能力单列待决策。

先完成分析和文件列表，再实施修改，避免一边扫描一边零散修补。

### 3. 按依赖顺序更新增强

#### 第一步：工具链与工作区基础

- 恢复 Bun、工作区依赖、模块解析、开发及构建测试入口、锁文件规则。
- 正式安装或构建前，先完成下一步的工具链遥测禁用。

#### 第二步：隐私安全限制

- 优先关闭工具链及应用内发现的遥测。
- 确认原有禁用配置没有丢失。
- B 类保持可用；C 类待决策项单列，其他独立工作继续。
- 不先运行工具或应用，再补禁用措施。

#### 第三步：底层功能与接口

- 先适配严格快进等 Git 引擎能力。
- 再对齐命令注册、IPC 和调用参数。
- 上游接口变化先落实到这一层，避免 UI 建立在过期接口上。

#### 第四步：数据状态与功能交互

- 恢复项目缓存、后台刷新、阅读状态和关闭生命周期。
- 保留请求过期保护。
- 将上游新增的项目相关状态纳入恢复逻辑。
- 接好菜单、按钮及快捷键行为。

#### 第五步：UI 与易用性

- 接口和状态稳定后，再恢复紧凑显示、国内头像及局部加载。
- 核对阅读位置和加载期间搜索。
- 与上游新布局、主题及滚动实现融合，不覆盖回旧组件。

#### 第六步：国际化

- 功能和界面确定后，统一翻译新增或变更文案。
- 补齐词典、错误说明、无障碍名称和测试选择器。
- 使用 `bun run localize --repo <源码目录>` 执行纯翻译。
- 文案涉及行为判断时同步修正，不能只替换显示文本。
- 上游同步、冲突处理及增强适配由本地人工完成。
- 不恢复 GitHub 自动检测、同步汉化或准备 PR 的工作流。

#### 第七步：中文版发布与说明

- 核对 fork 身份、下载及更新渠道、公钥、签名配置和版本声明。
- 适配合并后变化的构建与测试入口。
- 更新 README、网站及本清单，使说明对应最终实现。
- CI、网站部署和构建发布仅负责验证及交付。

以上是默认依赖顺序。不同分类共用一个配置文件时可以一次修改，但仍逐层核对。

每步运行直接相关的测试；发现失败立即定位，不把测试修复全部拖到最后。

### 4. 统一验证与交付

#### 验证范围

- 工具链：冻结安装、内部子包解析和相关脚本。
- 程序：文案检查、类型检查、单元测试和构建。
- Rust：涉及变更时运行格式、Clippy 和引擎测试。
- 交互：本次场景与完整界面回归，按需补真实桌面验证。
- 风控：A 类禁用、B 类保留、C 类新增能力的处理结论。

#### 交付记录

- 本轮上游基线。
- 功能逐项结论，包括完整保留和上游等价实现。
- 实际更新文件。
- 验证结果，区分失败、未执行和重试通过。
- 剩余问题，未解决项不得标为完成。

合并提交、推送和发布按用户指令执行。发布验证最终代码，不在发布过程中临时修改增强。
