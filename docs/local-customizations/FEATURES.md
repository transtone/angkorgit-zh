# angkorgit-zh 项目 fork 说明

## 一、指导方针

对上游软件进行国际化、易用性、隐私安全等方面的增强。

## 二、功能清单

以下列出本 fork 相对上游的增强和适配。功能状态以当前 0.27.2 为基线；风控中“未发现”的结论基于上游 `7afb6b6`，后续版本需要重新审查。

### 1. 工具链更新

- **统一使用 Bun：已实现。** 开发、构建、测试、CI 和发布命令统一使用 Bun 1.4.4，使用 Bun 锁文件固定依赖。
- **工作区适配：已实现。** 支持内部子包依赖、模块解析及统一构建，修复动态导入导致的测试错误。

### 2. 国际化

- **界面中文化：已实现，持续维护。** 包括菜单、按钮、提示、错误、空状态和无障碍名称。
- **文档与网站中文化：已实现，持续维护。** 包括 README、开发说明、路线图和网站内容。
- **中文词典与检查：已实现。** 唯一权威 JSON 词典 `zh-dict/zh-CN.json` 承接 1478 条迁移规则及上下文词条；按 AST 文件/组件/属性安全定位，支持已知旧译 `previousTargets` 和生成待译报告，不引入运行时 i18n。新增界面文案须同步登记词典，脚本不操作 Git、版本或发布地址。
- **“全部”提示：已实现。** 仅将提交详情“全部”按钮的提示调整为“显示全部变更”，按钮文字及其他“显示全部文件”用法保持原语义。

### 3. 易用性增强

- **紧凑显示：已实现。** 调整提交表格摘要、未提交更改摘要和菜单字号，提高信息密度。
- **国内头像源：已实现。** 将上游 Gravatar 替换为 Cravatar，保留头像缓存和失败回退。
- **双向严格快进：已实现。** 支持将当前分支快进到所选分支，或将所选本地分支快进到当前分支；拒绝分叉、覆盖本地修改和修改其他工作树占用的分支。
- **项目切换缓存：已实现。** 切回项目立即显示该项目的缓存数据，后台获取新数据并更新；刷新失败保留旧内容，允许重试。
- **恢复项目阅读状态：已实现。** 保留各项目的筛选、搜索、选中提交、提交对比状态及纵横滚动位置。
- **局部透明加载：已实现。** 加载反馈仅覆盖提交表格，保留底层内容，移除工作区白屏、模糊和强制等待。
- **加载期间搜索可用：已实现。** 表格加载时仍可通过 Ctrl/Cmd+F 聚焦搜索框；暂时阻止表格导航，其他区域保持可用。
- **过期远程跟踪分支：已实现。** 经认证只读查询确认远端已不存在后，图与侧栏使用灰色 CloudOff 和带完整远端前缀的提示；可单独删除本地跟踪引用，删除前重查远端并锁定核对 OID，网络失败保留未知状态。
- **标签远端状态：已实现。** 图与侧栏按远端独立显示已同步、仅本地、未知或同名对象不一致，比较标签直接 OID（包括附注、签名），支持后台及手动检查、选择推送远端；已同步禁用推送，不默认强推。维护与验证见 [06 远端引用状态](06-remote-ref-status.md)。
- **快速切换与异步更新保护：已实现。** 防止旧请求覆盖新项目、关闭标签后重新写回数据，或搜索结果覆盖用户的新选择。

### 4. 隐私安全增强与风控分类

#### A. 项目中存在，必须限制

- **网站工具链遥测：已显式禁用。** 关闭 Astro 开发、构建、预览和类型检查命令中的遥测。
- **统一政策：遥测必须禁用。** 包括使用统计、追踪及自动崩溃上报。

#### B. 项目中存在，无需限制

- **远程头像：允许。** 使用已替换的国内 Cravatar 地址，保留正常回退。
- **自动更新：允许。** 使用本 fork 的中文版更新渠道。
- **自动 Fetch 与远程 Git：允许。** 保留现有设置和仓库认证功能。
- **云 AI、本地 AI、外部 AI CLI：允许。** 属于可选辅助功能。
- **自托管与托管平台集成：允许。** 包括对应账号、凭据和现有协议适配。
- **现有 PR 辅助与 AI 审查：允许。** 包括 PR 列表、创建、指定评审人、检出、网页跳转，以及代码 AI 审查。

#### C. 项目中未发现，合并上游时监控

- **桌面遥测、自动崩溃上传及追踪上报：未发现。** 后续发现必须禁用。
- **产品强制注册或登录：未发现。** 指不登录就禁止使用本软件，不包括仓库或 AI 等辅助功能的凭据。
- **产品许可证、激活、订阅、付费墙和试用期限：未发现。** 关注是否限制本软件主要功能。
- **强制升级、最低版本封锁和远程停用：未发现。** 与允许的自动更新检查分别判断。
- **产品自有云端成为核心功能前置条件：未发现。** 不包括可选远程仓库、AI 等辅助服务。
- **完整应用内 PR Review：未发现。** 指行内讨论、批准、请求修改等完整流程；新增后需确认是否纳入。
- **插件市场与用户扩展加载器：未发现。** 新增后需确认是否纳入；不包括应用使用的静态 Tauri 插件。

### 5. 中文版发布适配

- **独立发布渠道：已实现。** 使用本 fork 的中文版下载与自动更新地址。
- **签名发布：已实现。** Windows 安装包及自动更新使用对应的签名配置。
- **版本一致性检查：已实现。** 仅推送 `vX.Y.Z` tag 触发中文版发布，核对 tag 与各应用清单版本一致。
- **发布验证与错误证据：已实现。** 发布前运行测试并构建 Windows 安装包，失败时保存测试结果；维护 Windows 清理兼容、部分 Fetch 测试夹具及无外网测试。
- **手动验证与网站交付：已实现。** CI 与 Website 仅手动触发；网站 `SITE_URL` 随仓库所有者及仓库名生成，Pages 须启用并选用 GitHub Actions 来源。上游同步人工执行，不另建独立同步文件。

## 三、合并与增强流程

整体顺序：先合并上游 → 按功能清单分析差异 → 形成分类文件列表 → 按依赖顺序更新 → 验证结果。

### 1. 先合并上游代码

- 记录合并前的 fork 提交、上次上游基线和本次上游目标，保留恢复本地增强所需的差异。
- 先完成上游代码合并和冲突解决，原则上以上游最新实现、结构及接口为准。
- 冲突处不为保住旧增强而退回旧实现；被覆盖的本地增强记录下来，在后续阶段按新结构恢复。
- 已经正常合并、没有冲突的增强不主动删除。上游优先也不等于把整个仓库替换成上游副本。
- 本阶段产出：无未解决冲突的合并代码、冲突处理记录和上游变更范围。此时不把增强恢复或构建验证标为完成。

### 2. 对照功能清单逐项分析

- 分析合并后的实际代码，逐条核对第二部分的功能清单；检查范围不能只限于冲突文件。
- 判断每项增强的状态：
  - **完整保留**：行为仍符合要求，不需要修改。
  - **上游已等价实现**：复用上游能力，不重复恢复旧代码。
  - **被覆盖或部分丢失**：列出需要恢复的行为。
  - **接口或结构变化**：列出需要按上游新结构适配的行为。
  - **待确认**：证据不足或新增能力尚未决定，单独记录。
- 按工具链、国际化、易用性、隐私安全、发布适配分类，形成待更新文件列表。
- 每个待更新项写明：对应功能、当前差异、预期行为、需修改的源码/配置/词典/测试文件，以及前置依赖。同一个文件涉及多项增强时合并安排，避免重复覆盖。
- 风控分别处理：
  - **A 类**：核对禁用是否保留；未禁用的列入修复列表。
  - **B 类**：保留正常功能，只恢复国内头像源、fork 更新地址等已确定适配，不额外增加限制。
  - **C 类**：检查本次是否新增。新增遥测直接列入禁用；其他需决策能力单列，不能自行判定接受或禁止。
- 本阶段先完成分析和文件列表，不一边扫描一边零散修改，避免遗漏和反复返工。

### 3. 按依赖顺序更新增强

1. **工具链与工作区基础。**
   - 恢复 Bun、工作区依赖、模块解析、开发/构建/测试入口和锁文件规则。
   - 先保证后续工作使用正确的工具链；正式安装、构建前先完成下一步的工具链遥测禁用。

2. **隐私安全限制。**
   - 优先关闭工具链及应用内发现的遥测，确认现有禁用配置未丢失。
   - B 类保持可用；C 类新增待决策项单独记录，其他独立工作继续进行。
   - 此步在运行相关工具或应用验证前完成，避免先运行再补禁用。

3. **底层功能与接口。**
   - 先适配严格快进等 Git 引擎能力，再对齐命令注册、IPC 和调用参数。
   - 上游接口变化先落实到这一层，避免 UI 建立在过期接口上。

4. **数据状态与功能交互。**
   - 恢复项目缓存、后台刷新、视图状态、请求过期保护和关闭生命周期。
   - 将上游新增的项目相关状态纳入恢复逻辑，再接好菜单、按钮及快捷键行为。

5. **UI 与易用性。**
   - 在接口和状态稳定后，恢复紧凑显示、国内头像、表格透明加载、阅读位置和加载期间搜索等体验。
   - 与上游新布局、主题和滚动实现融合，不直接覆盖回旧组件。

6. **国际化。**
   - 功能和界面确定后，再统一翻译新增/变更文案，补词典，并对齐错误、无障碍名称及测试选择器。
   - 使用 `bun run localize --repo <源码目录>` 执行纯翻译。上游同步、冲突处理和增强适配由本地人工完成；不再使用 GitHub 自动检测、同步汉化或准备 PR 的工作流。CI、网站部署和构建发布仅负责验证及交付。
   - 文案涉及行为判断时同步修正，不能只替换显示文本。

7. **中文版发布与说明。**
   - 核对 fork 身份、下载/更新渠道、公钥、签名流程和版本声明；适配合并后变化的构建及测试入口。
   - 更新 README、网站与本清单中的功能状态，使说明对应最终实现。

以上为默认先后关系；不同分类共用一个配置文件时可以一次修改，但仍按这些依赖检查。每步配套更新直接相关的测试，发现失败就定位处理，不把测试修复全部拖到最后。

### 4. 统一验证与交付

- 工具链：验证冻结安装、内部子包解析及相关脚本。
- 程序：运行文案检查、类型检查、单元测试和构建；涉及 Rust 时运行格式、clippy 和引擎测试。
- 交互：验证本次改动场景，并执行完整界面回归；按需要补充真实桌面验证。
- 风控：A 类确认禁用，B 类确认保留，C 类给出是否新增及处理结论。
- 最终输出：本轮上游基线、功能逐项结论、实际更新文件列表、验证结果和剩余问题。
- 完整保留及上游等价实现也要有结论，不以没有修改文件代替检查。失败、未执行、重试通过分别记录；未解决项不能标为完成。
- 合并提交、推送和发布按用户指令执行。发布验证最终代码，不在发布过程中临时修改增强。
