## 文件维护规则

1. 本目录记录“为什么、必须保留的行为、定位入口、恢复步骤和验证方法”，源码仍是实现事实来源。
2. 上游移动文件或改名时，按符号与行为查找新入口，更新专项清单；行号不作为恢复依据。
3. 文档中的“建议”“待实施”和“计划测试”不能记为已完成。实现合入后补充实际提交、测试结果及限制。
4. 上游已有等价实现时优先复用，只补缺失行为，不重复维护第二套功能。
5. 不将 `git checkout` 整体恢复源码文件、整提交重放或 `-X ours/theirs` 当成定制恢复方案。一个历史提交可能同时包含翻译、样式、功能和生成文件。
6. 用户工作区中与本轮同步无关的修改不覆盖、不自动归入 patch；历史记录中的路径不构成永久排除，当前相关修改按清单审查。

- 根 `package.json` 的 `packageManager` 为 `bun@1.4.4`，工作区脚本使用 `bun run --filter`；不恢复上游 pnpm 命令或 `pnpm.onlyBuiltDependencies`。
- 保留 `workspaces`、`trustedDependencies`，将 `bun.lock` 纳入版本管理。安装使用 `bun install --frozen-lockfile`；不要重新忽略锁文件，让 CI 每次从另一种锁文件迁移。
- CI、网站构建与中文版发布都使用 Bun 1.4.4；保留 Node 供既有 Node 脚本使用。改包管理器声明时要同时核对 Actions 初始化步骤。
