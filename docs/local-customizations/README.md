## 当前维护规则

### 文件维护规则

- 本目录记录“为什么、必须保留的行为、定位入口、恢复步骤和验证方法”。源码仍是实现事实来源。
- 上游移动文件或改名时，按符号与行为查找新入口，更新专项清单。行号不作为恢复依据。
- 文档中的“建议”“待实施”和“计划测试”不能记为已完成。实现合入后补充实际提交、测试结果及限制。
- 上游已有等价实现时优先复用，只补缺失行为，不重复维护第二套功能。
- 不将 `git checkout` 整体恢复源码文件、整提交重放或 `-X ours/theirs` 当成定制恢复方案。
- 一个历史提交可能同时包含翻译、样式、功能和生成文件。
- 用户工作区中与本轮同步无关的修改不覆盖、不自动归入 patch。
- 历史记录中的路径不构成永久排除，当前相关修改按清单审查。

### 功能记录格式

以 Markdown 源码直接阅读为准，不把标题、状态、时间和说明挤在同一行，也不用宽表格承载完整记录。

```markdown
#### 分支与标签交互优化

状态：已实现。
记录更新：2026-11-11。

- 悬停不改变原标签和数量按钮的位置。
- 浮层首项与原标签左上对齐，背景透明。
- 右键菜单打开期间保留来源浮层。

维护入口：[07 分支与标签交互优化](07-branch-tag-interactions.md)。
```

- 标题只写功能名，状态和日期独立成行。
- 每个行为一条，避免用多个分号串联不同要求。
- 维护入口放在行为之后；有多个链接时分别列出。
- “记录更新”表示本条文档最近核对时间，不表示实现或发布的日期。
- 实施时间有可靠证据时另记“实现日期”；不明时省略，不补猜测日期。
- 当前能力写入 FEATURES.md；历史批次按基线、变更、验证和限制分段记录。

### 执行入口

每次同步以 [FEATURES.md 的合并与增强流程](FEATURES.md#三合并与增强流程) 为准。

- 同步、冲突处理与增强适配在本地人工完成。
- 自动上游检测及同步汉化 PR 工作流已移除。
- 翻译仅运行 `bun run localize --repo <源码目录>`，不操作 Git。
- CI、网站部署和发布负责验证与交付。
