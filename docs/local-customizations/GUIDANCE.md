# 本地 patch 指导方案

总清单：[FEATURES](FEATURES.md)。操作步骤：[WORKFLOW](WORKFLOW.md)。风控子类：[05-risk-control](05-risk-control.md)。

## 目标与 patch 定义

更简单的做法：沿用 Git 合并、已有翻译词典和测试，由一份清单驱动适配；不额外维护一份完整上游源码，不为每轮同步复制历史补丁集。

本项目的 patch 指“fork 定制的恢复与验证”，包括配置、翻译、UI、功能及风控。它不是现成的统一 `git apply` 命令。当前机械翻译有脚本，其他定制仍需根据上游结构适配；本方案明确这些步骤，不声称已建立自动 patch 执行器。

## 分类与恢复策略

| 分类 | 权威条目 | 恢复策略 | 不采用的做法 |
| --- | --- | --- | --- |
| 工具链 | TL-* | 保留 Bun 版本、workspace、信任名单、锁文件与脚本；依赖变化后由 Bun 更新锁，检查真实子包解析 | 换回 pnpm 命令、忽略 bun.lock、以本机残留依赖证明安装正常 |
| 翻译 | ZH-* / 01 | 词典恢复稳定整句；新模板、上下文、错误及测试选择器人工适配 | 无差别替换标识符、把普通英文加入允许表、覆盖整份上游组件 |
| 功能补强 / UI | UI-* / 02 | 保留本地可见效果，接入上游新结构及主题修复 | 恢复历史整文件导致新功能丢失 |
| 功能补强 / 优化 | FN-* / 03、04 | 以行为和回归测试为准；上游有等价能力时只保留一个实现，补齐本地缺失语义 | 只保留菜单不保留引擎检查，或保留旧缓存却漏掉上游新状态 |
| 功能补强 / 风控 | RC-* / 05 | A 必须禁用；B 保留不额外限制；C 检查新增并按政策处理 | 所有联网一概禁用，或把“未发现”永久视为无需审查 |
| 发布维护 | RL-* | 保留 fork 身份、更新渠道、公钥、版本一致性与 Windows 发布能力 | 合并时换回上游下载地址、移动已有标签、发布时临时改源码 |

## 判定规则

- 先理解双方变化，再选择保留、适配或退役。`git merge` 自动成功也要查清单；文本不冲突不能证明行为未变化。
- 上游已等价修复：复用上游实现，保留本地测试，条目标为“上游等价接管”，附提交证据；不能直接删掉清单项目。
- 上游新增字段、视图或异步请求：检查对每仓库缓存、错误状态、关闭生命周期和迟到回调的影响。比较 `base`、搜索过滤及选中状态不能跨项目串用。
- 冲突逐块处理，不能统一 `-X ours/theirs` 或整体 checkout 一边作为默认恢复策略。翻译文档/网站也应迁入上游有效事实，而非只恢复旧副本。
- 安装包签名与 updater 公钥属于既有发布配置，检查路径及匹配关系，不输出私钥，也不在同步过程中轮换密钥。
- 独立验证本地 Git 无需产品登录。第三方凭据和 Git 作者姓名/邮箱不是产品授权，不能误禁。
- 尚未确认的上游变化写“待确认”，失败检查写“失败”，缺环境写“未执行及原因”；禁止把文档计划、通过的部分测试或测试重试写成全部完成。

## 自动化边界

- `scripts/localize.mjs` 由 Bun 执行，仅应用翻译词典、生成待译清单；允许工作区存在修改，不执行 Git 操作，不修改版本或发布地址。
- 上游合并、定制恢复和交付采用 [WORKFLOW](WORKFLOW.md) 的显式 Git 流程，逐项审阅并验证。
- CI、网站和发布工作流保留；翻译命令不会触发发布。

原有上游检测与自动 PR 工作流已移除，不再作为操作入口。

## 清单维护

每项使用稳定 ID，记录行为、源码入口、验收方法、状态和证据。文件移动时更新路径，保留 ID；新增定制先入清单，删除/被上游接管时说明原因。临时环境路径、历史测试数字和某次工作区状态只能放历史记录，不作为长期操作前提。

完成同步的标准：清单逐项有结论，相关行为得到验证，A 类无启用的遥测，C 类无未处理决策，完整检查结果明确，并有可追溯的上游 SHA 与最终代码提交。远程发布结果单独登记。
