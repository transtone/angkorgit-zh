# 07 分支与标签交互优化

状态：已实现。将分支标签、Git 标签（tag）显示、远端状态、引用浮层和快进菜单作为同一组易用性优化维护。功能登记见 [FEATURES](FEATURES.md)；严格快进的引擎约束见 [03](03-fast-forward.md)，远端状态的数据与查询约束见 [06](06-remote-ref-status.md)。本文件统一交互要求，专项文档维护各自实现细节。

## 整体目标

用户应能直接识别当前分支、本地与远端引用、标签同步状态，并从图表或侧栏完成一致的操作。后台检查和鼠标悬停不得让标签、数量或菜单跳动；提示只表达操作对象、状态与必要后果，不展示内部实现说明或检查历史。

## 分支标签显示

- 当前检出分支优先显示，只有对应分支带勾选标记，并使用实色填充；其他引用保留所在轨道颜色。
- 同一提交的同名本地分支与正常远端跟踪引用可合并，使用本地、云端图标说明属性。独立远端引用保留远端前缀，不能把不同远端混为一个来源。
- 过期远程跟踪引用独立显示为灰色、断云图标和虚线边框，提示“过期的远程跟踪分支”。右键“删除远程跟踪引用”仅删除选中的本地跟踪引用，执行前复核，不能误删本地分支或云端分支。
- 引用列空间不足时保留完整的数量入口 `+N`，名称允许截断；悬停不得扩大原标签、挤动数量或改变原行布局。

## tag 显示与远端状态

- 提交图和提交详情独立保留本地、origin、upstream 等各来源的真实标签指向，只按“提交 + 标签名”合并显示。同名标签指向不同提交时，各提交都显示，不跨提交去重。
- 标签存在本地来源时显示电脑图标，存在任意远端来源时显示一个云图标；本地、origin、upstream 同时在同一提交上时，仍只显示电脑和云两个来源图标。origin、upstream 平时不作视觉区分，悬停提示列出具体来源。
- 图表的来源图标来自最近成功 fetch 的独立标签引用，不由默认远端同步状态推断；获取失败保留上次结果。已有本地标签不被远端同名标签覆盖。侧栏的本地标签同步状态仍针对默认远端。
- 本地标签保留单级“推送到远端”与原有操作；仅远端标签提供检出对应提交和复制标签名，不以同名本地标签替代操作对象。
- 工具栏“推送（含标签）”沿用上游选中的默认远端与原有处理逻辑，不覆盖远端选择。
- 分支与 tag 的状态检查共用查询结果。重查期间保留已有显示，各远端独立更新；失败不能构造新的缺失证据，也不能让已确认的过期分支在正常与过期分组间反复切换。首次无结果及标签查询失败显示未知。

## 多引用浮层与右键菜单

- 更多引用在独立浮层中纵向紧密排列，项目之间无空白间隙，覆盖原标签位置；按实际矩形定位，首项左上角与原标签对齐，不用固定补偿值猜测位置。
- 浮层容器透明，各标签自身使用不透明的轨道色底色，仅遮住标签正下方的内容，标签外不增加矩形底板；无边框、阴影、内边距或位移动画。显示时隐藏原标签绘制但保留占位，避免半透明颜色叠加；`+N` 不移动。
- 限制浮层尺寸，超出时滚动；打开时抑制原生提示，避免提示框遮住引用列表。
- 引用与整行提交右键菜单标题统一使用对应提交的轨道色，过期引用使用中性灰；当前分支不照搬实色标签上的白字。标题使用加粗等宽字体和 `px-2 py-1`，长引用名允许换行，下方加细分割线；菜单背景和操作项保持原色。
- 双击和右键沿用图表与侧栏对应操作。右键菜单是引用浮层操作的延续：从浮层打开菜单后保持来源浮层，鼠标移向菜单不能触发延迟关闭；菜单关闭或操作完成后释放。

## 快进菜单

- 图表与侧栏使用相同的双向快进语义：当前分支快进到所选分支，以及所选本地分支快进到当前分支。
- 只展示实际可执行的方向。同一分支、相同提交、目标领先、分叉或目标被其他工作树占用时，不提供可执行快进入口。
- 菜单异步检查绑定仓库、来源与目标；旧菜单结果不能覆盖新菜单。操作仍由后端严格校验，不能用普通合并、重置或强制移动替代。详细安全要求以 [03](03-fast-forward.md) 为准。

## 合并上游时整体核对

| 层次 | 主要入口 | 核对内容 |
| --- | --- | --- |
| 图表显示与浮层 | `GraphRow.tsx` 的 `groupRefs`、`RefChip`、`RefCell` | 分组、当前分支、宽度、对齐、透明容器、不透明标签与菜单保持 |
| 图表与侧栏菜单 | `CommitGraph.tsx`、`Sidebar.tsx` | 双向快进、上游标签直接推送与各自远端选择、单引用删除；不额外添加标签检查或状态限制菜单 |
| 工具栏 | `components/Toolbar.tsx` | “推送（含标签）”保留上游选中的默认远端与处理逻辑 |
| 状态与提示 | `GraphRow.tsx`、`CommitDetails.tsx`、`repository/store.ts`、`TagRemoteStatus.tsx` | 图表/详情按真实引用合并来源图标与来源提示，侧栏保留默认远端同步状态，失败语义及过期响应保护 |
| Git 引擎 | `core/branch.rs`、`core/remote.rs`、`core/history.rs` | 严格快进、各远端独立标签引用与历史遍历、只读状态查询、直接标签对象比较与安全删除 |
| 文案 | `zh-dict/zh-CN.json` | 与源码同步维护，提示不包含实现细节 |

前端路径位于 `apps/desktop/src/features/`（工具栏位于 `apps/desktop/src/components/`），引擎路径位于 `apps/desktop/src-tauri/src/`。先核对上游是否已有等价能力，再按接口、状态、UI、文案和测试顺序恢复；不能只保留外观而遗漏安全检查或菜单生命周期。

- `tests/unit/staleRemoteRefs.test.ts`、`tagRemoteStatus.test.ts`、`staleRemoteChips.test.ts`：状态、分组、提示与请求保护。
- `tests/e2e/refLayout.spec.ts`、`staleRemoteRefs.spec.ts`、`tagRemoteStatus.spec.ts`：长名称、同步状态、删除及各入口实际目标状态与所有远端只读提示。
- `tests/e2e/tagPushUpstream.spec.ts`：本轮回归入口；需核对图表与侧栏单个直接推送操作、各自上游远端选择、工具栏原有默认远端，以及无额外手动检查、同步禁用或不一致警告菜单。

- Rust 的 `strict_fast_forward_*` 及 `stale_remote_refs`：真实临时仓库中的安全写入、远端恢复、对象不一致和查询失败。
